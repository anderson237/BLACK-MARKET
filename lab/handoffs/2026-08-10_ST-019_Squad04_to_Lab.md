## 2. Comportement implémenté (résumé)

- **Un fournisseur = une entrée unique** dans le blob `bm-suppliers`. Dédup par nom normalisé
  (`normalizeSupplierName`: trim, espaces multiples, lowercase) → `SUPPLIER-A` === `supplier-a`.
  Id : slug lisible (`xiao-nan-tech`) ou sha1 court si nom CJK. Chaque rencontre fusionne les
  infos sans écraser ce que l'admin a déjà saisi.
- **Capture auto** : lors de la publication d'un produit importé avec `seller`/`supplierContact`,
  le fournisseur est créé/mis à jour (`manual:false`) — productId ajouté, productCount incrémenté,
  contacts/plateformes/sourceIds/stats fusionnés. Jamais bloquant (try/catch).
- **Ajout manuel** : formulaire complet → `manual:true`, `productCount:0`, doublon de nom rejeté.
- **Édition** : tous champs modifiables, le champ `manual` est conservé (sauf override explicite).
- **Lien produit ↔ fournisseur** : accordéon dans la page avec jointure `productIds` sur le
  catalogue admin + lien direct vers la fiche vitrine `/p/{id}.html`.
- **Sécurité** : toutes les routes exigent `requireAuth` + rôle `admin` (pattern `carts.get.ts`).

## 5. Points d'attention pour la revue Lab

1. **Dédup strict par nom normalisé** : deux vendeurs homonymes (rare) fusionnent en un seul
   fournisseur. Les `sourceId` restent tracés dans `sourceIds` (couplage secondaire disponible
   pour un futur critère de fusion).
2. **Fusion additive / priorité admin** : un contact déjà saisi n'est jamais écrasé par un import.
3. **Renommage** : renommer un fournisseur auto ne re-câble pas les produits existants (lien par
   `productIds` conservé) ; un produit importé sous l'ancien nom créera un nouveau fournisseur.
4. **Pas de backfill** des imports passés : seuls les produits publiés après ce ticket alimentent
   `bm-suppliers`. Un script de ré-indexation peut être ajouté en cycle 2 si demandé.
5. **Suppression** : ne touche pas aux produits ni au `bm-supplier-contacts` ; un ré-import du même
   vendeur recrée le fournisseur.
6. **Occurrences d'échec** : l'upsert post-publication est best-effort (try/catch) — en cas
   d'échec blob, le produit est publié et le fournisseur sera rattrapé à la prochaine rencontre.
