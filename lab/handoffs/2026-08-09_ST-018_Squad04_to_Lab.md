## 2. Comportement implémenté (résumé)

- **Persistance** : mention optionnelle au niveau type + `sanitizeProduct` (allowlist). Toutes les
  routes d'écriture produits (create/update/import publish) convergent vers `sanitizeProduct` →
  une seule source de validation. Valeur invalide → `undefined` (champ non persisté).
- **Import** : `buildDraft` ajoute `suggestedMention` — proposé dans le modal d'aperçu, l'admin
  peut le garder ou le changer avant publication. Mention publiée sur le produit.
- **Vitrine** : badge coloré sur la carte ; pastille sur la fiche ; filtres « Tous / Neuf /
  Occasion / Gros » combinables avec catégorie et recherche (état vide adapté).
- **Rétrocompatibilité** : produits sans `mention` → aucun badge, inclus par défaut dans tous les
  filtres ; `sanitizeProduct` ne casse rien (champ optionnel partout).

## 5. Points d'attention pour la revue Lab

1. **Suggestion auto volontairement conservative** : un produit goofish avec état neutre
   (`itemStatusStr` = « 在线 ») ne reçoit **aucune** suggestion ; l'admin choisit (conforme spec
   « sinon pas de suggestion »). Affinages possibles en cycle 2 (taobao second-hand, douyin…).
2. **`condition` non persisté** sur le produit publié (draft/aperçu uniquement, inchangé). La
   séparation `condition`/`mention` est vérifiée par le test (scénario 5).
3. **Rendu carte** : pastille mention volontairement discrète (`text-[8px]`) pour ne pas
   concurrencer photo/prix. Ajustable si le Lab veut plus de présence (`ProductCard.vue`).
4. **Filtres** : l'onglet mention actif est violet (distinct du rouge catégorie). La recherche ne
   filtre PAS par le mot « neuf »/« occasion » dans le texte — uniquement par le champ normalisé.
5. **Sécurité** : `mention` est validée serveur (allowlist) sur toutes les routes d'écriture —
   aucune injection possible via `...body` (le champ est explicitement re-satisfait).
