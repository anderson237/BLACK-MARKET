# ST-013 — Cycle 1 : Temps réel site-wide + anti-flash + brouillon chat persistant

Date : 2026-08-07 — Par : Lab Director (orchestration), squads 1/2/4/5/9/10

## Demande utilisateur
> « Le chat marche bien mais il y a un refresh qui flashe dans tout le site. » (pendant la frappe d'un message, un rafraîchissement détruit le message) — et « pourquoi le chat est instantané alors que les stats/produits ne le sont pas ? » (temps réel site-wide souhaité).

## Root cause
- `/compte` : `v-if="loadingData"` démontait TOUTE la section activité (chat, panier, commandes) à chaque refresh (15 s / focus / événements) → le champ de saisie du chat était détruit → message perdu.
- Le chat est instantané (SSE + poll 2 s) ; le catalogue n'est chargé qu'une fois, `/compte` recharge 15 s, l'admin 12 s manuel. Aucune poussée stats/produits.

## Décisions techniques
- **Anti-flash/saisie** : `pages/compte.vue` → `v-if="loadingData && !data"` (squelettes seulement au 1er chargement ; les refresh gardent le contenu affiché).
- **Brouillon persistant** : `components/ChatPanel.vue` → `draftKey = bm_chat_draft_<side>_<threadId>`, restaure depuis `sessionStorage`, `clearDraft()` après envoi réussi.
- **Anti-FOUC thème** : `nuxt.config.ts` → script inline head avant premier paint (`bm_theme === 'light'` → classe `.light`).
- **Re-renders réduits** : `stores/chat.ts` + `stores/adminChat.ts` → `load()` ne mute que si `JSON.stringify` diffère (fin des mutations inutiles du poll 2 s).
- **SSE site-wide** : `server/utils/realtime.ts` → `publishSiteUpdate('catalog'|'orders'|'stats')` sur canal `site` ; endpoint public `server/api/events.get.ts` (`createEventStream`, ping 15 s, sans auth) ; publications sur toutes les mutations produits (post/put/delete/permanent/restore) et commandes (post/put/delete).
- **Client** : `composables/useSiteEvents.ts` (fetch `/api/events`, parse SSE, backoff 0.5s..5s, dispatch `CustomEvent bm:site` {kind, at}) démarré depuis `app.vue` (onMounted/onBeforeUnmount).
- **Écouteurs** : accueil `pages/index.vue` (kind `catalog` → `store.refresh()`, garde le scroll), fiche `pages/p/[id].vue` (kind `catalog` → `refresh()` + `navigateTo('/')` si disparu), `/compte` (kind `orders` → reload silencieux débouncé 400 ms), layout `layouts/admin.vue` (orders → `loadOrders`+`loadStats`, catalog → `loadProducts`).
- **Fallbacks poll** : constat e2e que le push Netlify est intra-instance (la mutation et la connexion SSE peuvent toucher des instances différentes) → accueil poll 30 s, fiche produit poll 60 s, admin conserve ses 12 s, `/compte` ses 15 s.

## Gates franchies
- Gate 2 (Données) : aucun changement de schéma ; endpoint public `/api/events` en lecture seule.
- Gate 3 (Implémentation) : serveur (realtime.ts, events.get.ts, mutations) + client (useSiteEvents, app.vue, pages).
- Gate 5 (Validation) : test e2e prod (voir ci-dessous).
- Gate 8 (Risque) : endpoint public ne divulgue que des signaux de type (`catalog`/`orders`/`stats`) sans données ; aucune donnée sensible en SSE public.
