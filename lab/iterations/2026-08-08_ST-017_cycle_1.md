# ST-017 — Pipeline d'import Xianyu / Goofish — Cycle 1

**Date** : 2026-08-08
**Gate courant** : 1 → 3 (Hypothèse + Web research)
**Statut** : 🚧 En cours — en attente de décision de méthode (utilisateur)

## Objectif
Permettre à l'utilisateur d'importer **~150 produits/semaine** depuis Xianyu (闲鱼 / Goofish, `https://www.goofish.com/`) vers le catalogue Deep Roots, avec : images re-téléchargées (pas de hotlink), conversion prix CNY → XOF, traduction/enrichissement Gemini, catégories et publications propres.

## Rappel du problème
Xianyu est une plateforme mobile-first d'Alibaba (C2C, millions d'annonces). L'utilisateur propose 2 options initiales :
- **Option 1** : simulateur + capture du trafic de l'app (Interception TLS)…
- **Option 2** : APK maison installé sur son téléphone, qui écoute le trafic de l'app Xianyu, pour récupérer les données et les pousser vers le site.

Les deux sont **déconseillées**. ⇒ Raisons : violation des CGU Xianyu/Alibaba, détection anti-bot (TLS fingerprinting, captcha), fragilité à chaque mise à jour d'app, risque juridique, et non maintenable à `à cadence 150/semaine`.

## Recherche (gate 3) — état des fait
1. **Pas d'API publique officielle pour LIRE le marketplace Xianyu** : la « Xianyu Open Platform » (淘宝开放平台) n'expose que des API **ISV** réservées aux partenaires (expose : `alibaba.idle.isv.item.publish/edit/query/downshelf`, `alibaba.idle.isv.media.upload`… sur open.fliggy / developer.alibaba.com) — orientées **publication** de produits pour des vendeurs accrédités (准入), pas du « scrape ».
2. **API tierces / scraping managé** pour récupérer données de listing :
   - JustOneAPI : `https://api.justoneapi.com/api/xianyu/search-item-list/v1?token=...&keyword=...` (search) et `/api/xianyu/get-item-detail/v1?itemId=...` (détail).
   - Apify « Goofish Scraper » / « Xianyu Listings Scraper » (per-tél/ per-volume : ~$2/1000 listing, ~$6/1000 détail ; acteur sans login pour feed).
   - Projets open-source (MCP + Playwright + MTOP) : faisable mais maintenance anti-bot.

## Options à décider (synthèse utilisateur)
- **A. Usine à scraping / bulk** : acteur Apify/JustOneAPI sur des mots-clés (candidates à cadence haute) → pipeline complet (volumétrie 80+ produits/h). Coût €/ semaine faible (~0,5–5 €/1000 selon profondeur). Nécessite API token provider (compte payant à créer).
- **B. Agrégateur par liens** : l'utilisateur colle ~150 URLs Goofish par semaine dans l'admin → scraper par-ID (acteur ou mini-serveur) → enrichissement Gemini → preview → publier. Coût très faible, contrôle humaine total, tempo : ~10 min de collecte + prévis.
- **C. Officiel (oportunité long-terme)** : demande d'accréditation ISV Xianyu (de robe pour l'import mondial limitéeish) — à réévaluer.

## Décisions prises
- Pas d'introduction de credentials en dur ; prévoir `.env` `XIANYU_PROVIDER_TOKEN` (placeholder) en dégradation gracieuse comme PayUnit/RESEND.
- Architecture server-side : route `/api/admin/import` (auth admin) + `server/utils/ingest-xianyu.ts`, rejet des images via `loadImage/saveImage` ou stockage obj, conversion CNY→XOF par API ou sin taux fixe.

## Prochaines étapes
1. Blocage décisionnel : utilisateur choisit **A (bulk)** ou **B (liens)** et fournit type de compte Xianyu (buyer vs seller) + accepte un fournisseur de scraper (Apify / JustOneAPI / code maison piloté MCP).
2. Selon choix : première itération = importer 10 produits réalistes bêta, puis montée à 150/semaine.
3. Reçu pour PayUnit : test e2e sandbox dès que les credentials API USER/PASSWORD sont validées côté PayUnit.
