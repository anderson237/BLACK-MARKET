## Objet

Livrer l'**extension Chrome MV3** (BL-010) qui scrappe les produits depuis le
navigateur CONNECTÉ de l'admin pour les sites non atteignables par URL
(Taobao/Tmall, 1688, Amazon, Goofish, Douyin, TikTok Shop), en réutilisant le
pipeline d'import existant (aucune duplication de logique).

## Ce qui a été fait

### Côté serveur (sous-git, non commité)
- `server/api/admin/import/extension.post.ts` — route `POST /api/admin/import/extension` :
  rate-limit (60/min/IP), auth `x-ext-key` (temps constant) **ou** Bearer admin, validation
  stricte du body, réutilisation de `buildDraft` pour TOUT (conversion XOF, transport,
  catégorie auto, contact fournisseur, mention suggérée). Retour draft au format identique à
  `/api/admin/import/from-url`. **Publication jamais directe** (`publish.post.ts` inchangé).
- `server/utils/extensionImport.ts` — logique portable (sans globals Nitro) :
  `parseExtensionPayload` (allowlist 6 plateformes, devises CNY/EUR/USD, images ≤ 5 URLs,
  hôtes autorisés **par plateforme**, longueurs bornées), `buildDetailFromExtension`
  (mapping → `JoDetail`, contrat identique pipeline), `authorizeExtension` (fallback dev
  documenté `bm-ext-import-dev-key` ; en production sans `EXTENSION_IMPORT_KEY` → 401
  explicite), `ExtensionImportError`.
- `scripts/test-extension-import.ts` — 3 scénarios, **56/56 assertions ✅** :
  1. draft complet payload Taobao simulé (prix converti via `loadRates`, transport
     « Écouteurs », catégorie auto CJK, mention `neuf`, 1688→`gros` auto) ;
  2. auth : 401 (absente/incorrecte/prod-sans-clé), clé dev OK, Bearer admin OK, non-admin 403 ;
  3. payload invalide : 18 cas → 400.
- `server/utils/draftBuilder.ts` : `DraftSource.detailSource` étendue `'justone'|'headless'|'extension'`
  (adaptation additive ; sortie `buildDraft` inchangée).

### Côté extension (`browser-extension/`)
- `manifest.json` — MV3, permissions `storage` uniquement, `host_permissions` bornées aux 7
  marketplaces + DeepRoots ; **2 entrées content_scripts** au `document_start` :
  `world: "MAIN"` (hook réseau) + `world: "ISOLATED"` (extraction) ; service worker +
  popup. PAS de `<all_urls>`.
- `content-main.js` — world MAIN : monkey-patch `window.fetch` + `XMLHttpRequest`
  (interception des réponses des API internes, filtre par sous-chaîne `mtop/detail/offer/item/…`),
  `res.clone()` (ne consomme pas la réponse), body ≤ 64 Ko, `window.postMessage`
  `{source:'dr-ext', type:'network'}` vers le monde isolé. Hook posé une seule fois.
- `content-isolated.js` — world ISOLÉ : pool borné (60 entrées) des JSON capturés, sélection
  du candidat par score (title/price/image/seller/desc), extraction heuristique par deep-search
  (`TITLE_KEYS/PRICE_KEYS/IMG_KEYS/COND_KEYS/CAT_KEYS/SELLER_KEYS`), **fallback DOM**
  (sélecteurs par plateforme), détection plateforme par host, sourceId depuis l'URL,
  devise auto (CNY / EUR amazon-Europe / USD), seller/condition/category. Répond à
  `DR_PING` et `DR_CAPTURE` via `chrome.runtime.onMessage`.
- `background.js` — service worker : reçoit `DR_IMPORT_DRAFT`, ré-applique une validation
  minimale (défense en profondeur), `fetch` POST (le fetch croisé ne vit QUE ici, via
  `host_permissions` — jamais dans un content script) avec header `x-ext-key`, retourne
  `{ ok, draft }` ou `{ ok:false, error }`.
- `popup.html` / `popup.js` — clé + base URL (`chrome.storage.local`), détection du host
  actif (DR_PING), bouton **Importer ce produit** (DR_CAPTURE → DR_IMPORT_DRAFT), affichage
  du draft (titre, prix FCFA, transport, catégorie, mention, miniatures), boutons
  **Ouvrir l'aperçu import** (`/admin/import`) et **Copier le JSON**.
- `README.md` — installation Load unpacked, config de la clé, flux, architecture, sécurité,
  limites v1.
