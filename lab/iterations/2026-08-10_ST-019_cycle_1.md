## Objectif
Ajouter une section **Fournisseurs** dans le dashboard admin : liste (nom, catégorie, pays,
plateformes, contacts, nb produits), **ajout manuel**, **capture auto** à l'import
(`seller` + `supplierContact` → fournisseur unique dédupliqué), **édition**, **suppression**,
et **liste des produits associés** par fournisseur — sans casser ST-018 (mentions) ni ST-017
(seller/sourceUrl éditeur produit).

## Ce qui a été fait

### 1. Modèle + persistance (`server/utils/storage.ts`)
- Interface `Supplier` complète (spec Lab) : `id`, `name`, `category`, `country`, `platforms`,
  `sourceIds`, contacts (`wechat`/`email`/`whatsapp`/`phone`/`website`/`note`), `productIds`,
  `productCount`, `stats` (soldCount, replyRatio24h, newGoodRatioRate, zhimaVerified,
  lastSeenAt), `manual`, `createdAt`, `updatedAt`.
- Blob **`bm-suppliers` / `suppliers.json`** (à côté de `bm-supplier-contacts`), fichier local
  `data/suppliers.json` — pattern identique aux stores ST-017.
- `listSuppliers()`, `saveSuppliers()`, `upsertSupplierFromProduct(product)`,
  `createSupplier(input)`, `updateSupplier(id, patch)`, `deleteSupplier(id)`.
- **Dédup par nom normalisé** : `normalizeSupplierName()` (trim + espaces multiples + lowercase)
  → `SUPPLIER-A` == `supplier-a`. Id dérivée (slug lisible `xiao-nan-tech` ou sha1 court pour un
  nom CJK). Doublons résiduels purgés au passage (1 entrée par nom).
- **Fusion** (`mergeSupplierInfo`) : ne remplit un champ que s'il est VIDE (ne jamais écraser une
  valeur éditée par l'admin) ; ajoute le `productId` (unique) ; incrémente `productCount` ;
  fusionne plateformes/sourceIds/stats seller ; `category` suggérée depuis le produit seulement
  si absente ; `lastSeenAt` mis à jour.
- `manual` : `false` pour capture auto, `true` pour ajout manuel, conservé et éditiable (PUT).
- Écritures via `mutateGeneric` (local: `withLock`, prod: `withBlobLock`) — pas de course
  read-modify-write entre publications concurrentes.

### 2. Routes admin (toutes protégées `requireAuth` + rôle admin)
- `server/api/admin/suppliers.get.ts` — liste triée par `updatedAt` desc, filtre `?auto=true|false`.
- `server/api/admin/suppliers.post.ts` — création manuelle (`manual: true`), nom requis, doublon
  de nom normalisé → **409**.
- `server/api/admin/suppliers/[id].put.ts` — édition (nom, catégorie, pays, plateformes, contacts,
  note, `manual?`), fournisseur inconnu → 404, doublon de nom → 409.
- `server/api/admin/suppliers/[id].delete.ts` — suppression (les produits associés ne sont pas
  supprimés ; un ré-import recrée le fournisseur via upsert).

### 3. Hook capture auto (`server/api/admin/import/publish.post.ts`)
- Après persistance produit : si `product.seller || product.supplierContact` →
  `upsertSupplierFromProduct(product)` **en try/catch strictement best-effort** — une erreur du
  blob fournisseurs est loguée (`[SUPPLIERS] upsert from publish failed`) et **ne bloque jamais
  la publication**.

### 4. Page admin (`pages/admin/suppliers.vue`, style `pages/admin/carts.vue`)
- Liste : nom, badges MANUEL/AUTO, catégorie, pays, plateformes, nb produits, chips contacts

- Recherche libre + filtre **Tous / Auto / Manuel** (appel serveur `?auto=`).
- KPI : total, auto, manuels, produits liés.
- Modal **création** + **édition** (tous les champs), suppression avec confirmation.
- Accordéon **PRODUITS** : jointure `productIds` ↔ store admin produits, lien vers la fiche
  vitrine (`/p/{id}.html`).

### 5. Menu admin (`layouts/admin.vue`)
- Lien « Fournisseurs » (icône `link`) dans `navItems`, entre « Import Chine » et « Réglages »
  (dessert : sidebar desktop + drawer mobile automatiquement).

## Limites / points d'attention (revue Lab)
- **Dédup strict par nom normalisé** : deux vendeurs homonymes (rare) sont fusionnés en un seul
  fournisseur. Le couplage secondaire `sourceId` est conservé dans `sourceIds` mais n'est PAS un
  critère de dédup (conforme spec « dédupliquée par nom/nick ou sourceId » — retenu le nom, la
  source reste tracée).
- **Champs créés par l'admin ont priorité** : une fois un contact renseigné (manuel ou via PUT),
  une nouvelle rencontre import ne l'écrase pas (fusion additive). Pour "forcer" une valeur il
  faut passer par l'édition.
- **Renommer un fournisseur auto** ne re-câble pas les produits existants : le lien est par
  `productIds` (déjà stockés), mais un prochain produit du même vendeur sous l'ancien nom
  créera un nouveau fournisseur (comportement dédup attendu).
- **Suppression** : les produits associés ne sont pas touchés ; le `bm-supplier-contacts`
  (contact par produit) reste intact — une nouvelle publication du même vendeur recrée le
  fournisseur.
- **Pas de backfill** des imports passés : seuls les produits publiés APRÈS ce ticket alimentent
  `bm-suppliers`. Un script de ré-indexation (produits existants → upsert) est trivial si le Lab
  le demande (cycle 2).
