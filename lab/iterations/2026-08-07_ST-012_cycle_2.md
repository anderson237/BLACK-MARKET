# ST-012 — Cycle 2 : Chat par article + chat général + verrouillage livraison

Date : 2026-08-07 · Par : Lab Director (orchestration), squads 1/2/4/5/9/10

## Demande utilisateur
> « Chat par article de précommande, l'affichage peut se faire comme les commentaires d'une page produit : en appuyant sur le bouton message ça développe la discussion et on peut voir les anciens messages et poster de nouveaux. Gère tout ça 1 2 3 » (les trois : chat général, chat par article, désactivation à la livraison).

## Décisions techniques
- Nouveaux formats de threads : `pre:<userId>:<productId>` (par article), `general:<userId>` (chat général). `ChatThread.kind` étendu : `'preorder' | 'order' | 'general'` + champ `productId?`.
- Verrouillage : `order.status === 'completed'` → serveur refuse 400 (« Commande livrée — discussion fermée. ») côté client et admin ; UI : prop `locked` sur ChatPanel (lecture seule) + icône lock.
- Migration à la confirmation : fusion de TOUS les fils pre (legacy + par article) vers le fil ordre, dédupe par `m.id`, `clientReadTs`/`adminReadTs` = max conservés.
- UI client : accordéons par article dans l'onglet Précommandes (bouton Message), onglet Chat général, badge lock sur commandes livrées.
- UI admin : `/admin/carts` chat par article + chat général par panier ; `/admin/orders` ChatPanel `:locked` sur statut `completed`.

## Gates franchies
- Gate 2 (Données) : blob `bm-chat` inchangé, schéma étendu rétro-compatible (kind legacy `preorder` sans productId = fil panier).
- Gate 3 (Implémentation) : `server/utils/storage.ts`, `server/utils/chat.ts`, routes threads/messages client+admin.
- Gate 5 (Validation) : test e2e prod (voir § test).
- Gate 8 (Risque) : aucune suppression de données ; migration non destructive ; lock serveur = filet de sécurité.
