## Objectif
Permettre aux clients de payer leurs précommandes en ligne (Mobile Money / carte) via la hosted page **PayUnit**, en complément du flux WhatsApp existant.

## Décisions de conception
- **Hosted checkout** (pas d'API make-payment directe) : l'utilisateur est redirigé vers la page de paiement PayUnit (`data.redirect`, valide 15 min), puis revient via `success_url`/`cancel_url`.
- **Prix calculés côté serveur** : `POST /api/payments/initialize` recharge les produits réels depuis le catalogue (`loadProducts`) — jamais de prix envoyé par le client (sécurité gate 8).
- **Idempotence** : un `PaymentRecord` (blob `bm-payments`) lie `checkoutId ↔ transactionId ↔ userId ↔ orderIds`. Le marquage `payment.status = 'paid'` sur les commandes n'a lieu qu'une seule fois (vérifié via `payment.status !== 'paid'`).
- **Webhook sécurisé** : `notify_url` ne fait JAMAIS confiance au payload ; il confirme le statut réel via `GET /api/gateway/checkout/status/{checkout_id}` avant de marquer payé.
- **Panier nettoyé au paiement** : après un SUCCESS, les produits payés sont retirés du panier de l'utilisateur (statut GET + webhook).
- **Dégradation gracieuse** : tant que `PAYUNIT_API_USER` + `PAYUNIT_APP_TOKEN` ne sont pas configurés, `payunitEnabled` est false → boutons PAYER masqués, routes → 503.
- **Devise** : PayUnit attend `XAF` ; le site est en `XOF` — même valeur CFA, montant passé tel quel.

## Fichiers
- `server/utils/payunit.ts` — client HTTP PayUnit (init + status + headers Basic/x-api-key/mode).
- `server/utils/storage.ts` — `PaymentRecord`, `loadPayments`, `savePayments`, `mutatePayments` (blob `bm-payments`).
- `server/api/payments/initialize.post.ts` — création des commandes pending + init checkout + enregistrement.
- `server/api/payments/status.get.ts` — vérification statut + marquage paid + purge panier (idempotent, ownership vérifiée).
- `server/api/payments/webhook.post.ts` — notify_url (statut confirmé via API).
- `pages/paiement/retour.vue` — page de retour (succès/annulé/échec/en attente).
- `pages/compte.vue` — boutons **PAYER** / **PAYER TOUTES** + badge « Payée » sur les commandes.
- `nuxt.config.ts` — runtimeConfig serveur `payunit.*` + `public.payunitEnabled`.
- `.env.example` — documentation des variables.
- `lab/status_board.md` — ligne ST-016 + deploy `6a76a74593cb36869edd8f6e`.
