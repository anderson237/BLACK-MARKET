# ST-014 — Cycle 1 : Suppression commandes + suppression comptes + UI dashboard client + sécurité admin

Date : 2026-08-07 — Par : Lab Director (orchestration), squads 1/2/4/5/8/9/10

## Demandes utilisateur
1. « Le bouton supprimer des commandes ne marche pas. »
2. « Il faut ajouter un bouton pour supprimer des comptes, même ceux ajoutés par email doivent être supprimables. »
3. (Pendant l'itération) « Dans le dashboard client, onglet précommande, il faut retirer le bouton Discuter de mes précommandes (chaque précommande a déjà son bouton Message individuel) ; l'onglet Chat doit être renommé Chat avec l'administrateur. »

## Root causes
- **Bouton supprimer commande** : les boutons liste (`/admin/orders`, lignes 228/253) posaient `deleting = o.id` mais AUCUN dialogue de confirmation n'existait dans le template → rien ne déclenchait `remove()`. Le bouton du modal détail fonctionnait (appel direct) — d'où l'incohérence.
- **Suppression comptes** : fonctionnalité inexistante (pas de route, pas de bouton).
- **Sécurité (trouvé en investiguant)** : `requireAuth` ne vérifie PAS le rôle. 9 routes admin-only (`orders.get`, `orders/[id].put`, `orders/[id].delete`, `products.post`, `products.put`, `products/[id].delete`, `products/[id].permanent`, `products/[id].restore`, `stats.get`) n'avaient que `requireAuth` → n'importe quel client connecté pouvait supprimer des commandes, modifier/supprimer des produits, lire TOUTES les commandes clients et les stats business.

## Décisions techniques
- **Fix suppression commande** : modal de confirmation (z-60) déclenché par `deleting`, bouton « Supprimer » → `remove()` avec ref `removing` (spinner, anti double-click) ; le bouton du modal détail route aussi par la confirmation.
- **Suppression comptes** : `server/api/users/[id].delete.ts` (admin only) — résout le compte par id OU email (tous providers), supprime : compte canonique (`bm-accounts`), entrées legacy (`bm-users` logins/accounts), panier (`deleteCart`), threads chat (`bm-chat`). Garde-fous : propriétaire (400) et auto-suppression (400). Les commandes sont CONSERVÉES (historique commercial, noms/téléphones dénormalisés) ; commentaires/événements restent (rendus « Anonyme »). Store `deleteUser` + bouton **Supprimer** dans `/admin/users` (masqué pour owner/self/admins) + modal de confirmation.
- **UI dashboard client** : bouton « DISCUTER DE MES PRÉCOMMANDES » supprimé ; badge non-lus Précommandes limité aux fils par article (`t.productId` présent) ; onglet « Chat » → « Chat avec l'administrateur ».
- **Sécurité (gate 8)** : pattern admin ajouté sur les 9 routes : `session = await requireAuth(event)` + `if (session.role !== 'admin') throw 403`.
- **Light mode bulles chat** (demande précédente incluse dans le même deploy) : exception `bg-[#ff2a2a]/90` (texte blanc conservé sur rouge), override `bg-[#1c1c26]` (bulle reçue claire en light), `bg-black/20` (fond panneau).
